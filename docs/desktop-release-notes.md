pre-midi desktop preview uses Tauri with the existing studio and bundled local assets.

- Windows 11 x64: per-user NSIS installer and portable ZIP. WebView2 Runtime is required; it is normally present on Windows 11. Keep the extracted ZIP together.
- Windows portable preview.3: app-managed presets, settings, drafts, recordings and WebView caches now stay in `data/webview` beside the executable, with `projects` and `exports` as save defaults. Close the app before moving or copying the master folder. Updates must retain those three directories. The installer and other portable folders use separate profiles. Earlier preview data stays untouched in AppData; see [migration and backup instructions](https://github.com/natanai/pre-midi/blob/main/docs/desktop-host.md#storage-and-backups) before replacing an older preview. WebView2 and Windows system files remain OS-managed.
- macOS 15.4+: separate Intel (x86_64) and Apple Silicon (aarch64) DMGs. Unsigned previews may be blocked by Gatekeeper; Apple signing/notarization is not configured.
- Linux x86_64: AppImage and DEB, built on Ubuntu 22.04. WebKitGTK 4.1 and desktop audio dependencies are required. AppImage compatibility and physical devices remain under qualification.

Preview.4 adds native C++ synthesizer playback through miniaudio: WASAPI on Windows, CoreAudio on macOS, PulseAudio/ALSA on Linux. Select a supported preset such as Init, Triangle Keys, Touch Keys, Sub Bass, Square Bass or Harmonic Keys, add notes and press Play. Hear sound also uses native output and can play over the transport. Native pause/resume and Song ruler seeking are available; output selection and optional sample-rate/buffer controls are in Settings. Native playback uses a snapshot taken at Play; restart after edits.

Canonical oscillators/harmonics, ADSR/note-off, pitch curves, v2 modulation, v3 cutoff automation, gain/pan, 64-voice allocation and loop release overlap are supported. Noise, filter sweeps, drive/oversampling, delay, legacy vibrato/tone/tremolo, samples and recorded/vocal playback remain unsupported in native mode. A project using them is rejected explicitly; select Web Audio in Settings to retain its existing sound. The original Sine Keys default contains delay and is therefore currently unsupported in native mode. No generator is substituted automatically. WAV export, standalone microphone workflows and Song recording retain Web Audio; native Song recording alignment is pending.

Automated device tests use miniaudio's explicitly selected null backend and validate callback execution, finite/nonzero PCM, timing semantics and allocation assertions. They do not establish physical output, driver underruns, end-to-end latency, sustained playback or sleep/resume on Windows 11/macOS/Linux. The bounded offline C++ fixture remains a separate proof, not the device test.

Settings displays the packaged application version and checks official GitHub Releases. Stable and preview channels are separate; downgrades are refused. Automatic installation requires a configured trusted signing key and a signed package. Portable Windows ZIP and Linux DEB editions use manual replacement/package-manager installation. Updates never deliberately remove user data.

These are testing builds. Automated packaging and WebView smoke checks do not establish microphone quality, hardware audio latency, human listening quality, Windows 11 installation/upgrade reliability or all-platform compatibility. Do not treat this prerelease as stable. Export music ZIPs to back up external WAV assets and projects before testing.
