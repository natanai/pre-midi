pre-midi desktop preview uses Tauri with the existing studio and bundled local assets.

- Windows 11 x64 portable ZIP only. Extract the complete folder to a writable location and open `pre-midi.exe`. WebView2 Runtime is required; it is normally present on Windows 11.
- App-managed presets, settings, drafts, recordings and WebView caches stay in `data/webview` beside the executable. `projects` and `exports` are local save defaults. Close the app before moving, copying or backing up the master folder.
- To upgrade preview.4: close pre-midi, back up the folder, replace only `pre-midi.exe`, `portable.txt` and `README.txt` from this ZIP, keep `data`, `projects` and `exports`, then open pre-midi manually. Do not delete the old folder or overwrite its data directories. Earlier preview.1/.2 data remains in AppData; see [migration and backup instructions](https://github.com/natanai/pre-midi/blob/main/docs/desktop-host.md#storage-and-backups).
- Installers and macOS/Linux artifacts are deferred during rapid prototyping. Their native architecture and package configurations are retained for the full release.

Preview.5 includes the native filter sweep and loop-restart timing improvements added after preview.4. The native v4 execution packet supports exponential filter cutoff sweeps, including alongside cutoff automation, without changing the saved Beat/Song formats. The filter sweep restarts on each loop cycle. This preview is for listening tests, not yet physical-device audio qualification.

Preview.4 introduced native C++ synthesizer playback through miniaudio: WASAPI on Windows, CoreAudio on macOS, PulseAudio/ALSA on Linux. Select a supported preset such as Init, Triangle Keys, Touch Keys, Sub Bass, Square Bass or Harmonic Keys, add notes and press Play. Hear sound also uses native output and can play over the transport. Native pause/resume and Song ruler seeking are available; output selection and optional sample-rate/buffer controls are in Settings. Native playback uses a snapshot taken at Play; restart after edits.

Canonical oscillators/harmonics, ADSR/note-off, pitch curves, v2 modulation, v3 cutoff automation, gain/pan, 64-voice allocation and loop release overlap are supported. Noise, drive/oversampling, delay, legacy vibrato/tone/tremolo, samples and recorded/vocal playback remain unsupported in native mode. A project using them is rejected explicitly; select Web Audio in Settings to retain its existing sound. The original Sine Keys default contains delay and is therefore currently unsupported in native mode. No generator is substituted automatically. WAV export, standalone microphone workflows and Song recording retain Web Audio; native Song recording alignment is pending.

Automated device tests use miniaudio's explicitly selected null backend and validate callback execution, finite/nonzero PCM, timing semantics and allocation assertions. They do not establish physical output, driver underruns, end-to-end latency, sustained playback or sleep/resume on Windows 11/macOS/Linux. The bounded offline C++ fixture remains a separate proof, not the device test.

Settings displays the packaged application version and checks official GitHub Releases. Stable and preview channels are separate; downgrades are refused. This portable edition reports available releases and requires the folder-preserving manual replacement above. Automatic installation and update signing remain unqualified; no downloaded executable is run by the update check. Windows code signing is not configured, so SmartScreen may warn about this unsigned testing build.

These are testing builds. Automated packaging and WebView smoke checks do not establish microphone quality, hardware audio latency, human listening quality, Windows 11 installation/upgrade reliability or all-platform compatibility. Do not treat this prerelease as stable. Export music ZIPs to back up external WAV assets and projects before testing.
