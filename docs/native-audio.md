# Native audio playback

Desktop Play and Hear sound default to C++ synthesis in miniaudio's playback callback. The browser version retains Web Audio. Settings retains an explicit Web Audio mode. The existing studio, canonical parameter IDs, project formats and saved data paths are preserved. All factory synth and sample presets use native output. Sine Keys and Sine Bell now play natively with their authored delay.

## Device boundary

miniaudio 0.11.25 is pinned by immutable commit and SHA-256 in scripts/fetch-miniaudio.mjs. Its device-only C API avoids a UI rewrite and hosts the existing framework-neutral C++17 Voice. We choose upstream's MIT-0 licence. JUCE adds an unnecessary application framework/licensing surface; CPAL would add a second native audio abstraction around the existing C++ core. native/host-comparison.json records the decision and distinguishes measured software callbacks from unmeasured physical backends.

Production selects WASAPI (Windows), CoreAudio (macOS), PulseAudio/ALSA (Linux), never a null/silent fallback. Device open failures are errors. The explicit test host flag selects miniaudio's null backend; desktop smoke additionally requires PREMIDI_SMOKE_OUTPUT. Its results always identify a test backend and cannot qualify hardware.

Windows Rust and C++ builds statically link the Visual C++ runtime, and CI inspects the PE dependencies to reject MSVCP/VCRUNTIME/CONCRT DLL requirements in the portable executable. WebView2 and Windows system components remain OS dependencies. C++ exception unwinding is enabled for control-side validation; Windows min/max macros are excluded at the native boundary.

Tauri's native_audio command sends requests through an eight-message bounded queue to one dedicated audio control thread. C API initialization, configuration, preparation and destruction stay on that thread, preserving backend/COM affinity. Blocking IPC workers wait for replies; the audio callback never touches the Rust queue. Shared native JS encoding carries the existing pre-midi-synth-voice v1/v2/v3 contract plus backward-compatible v4 filter sweep, v5 noise, and v6 delay execution packets in a bounded little-endian transport; this is not a new project/music format. Native packet validation independently checks counts, finite values, rates, routes, wave IDs and time bounds.

## Real-time ownership

Parsing, JSON, allocation, wave-bank FFTs, initial filter coefficients and modulation smoothing coefficients are control work. Published sessions own immutable plans and tables plus fixed-size callback state. Separate transport and preview lanes each have 64 logical voices and 64 retiring voices. Each lane has three control-owned session slots: active, fading predecessor and pending. The callback publishes the new active pointer before clearing pending; control reads pending before active/retiring and never frees a visible pointer. C++ atomic counters, controls and pointers are statically required to be lock-free.

The callback mixes blocks of at most 128 frames. Device callbacks above 8192 frames are silenced and counted instead of allowing unbounded synth work. Each lane has a 256-onset callback budget; preparation rejects excess onset density, more than 4096 notes per cycle, more than 32 unique banks, packets above 16 MiB, voices beyond 30 seconds or sessions beyond 10 minutes. Retirement-capacity/onset faults stop the session and are reported; unsupported density never silently drops notes. There are no callback heap allocations, locks, files, JSON parsing, UI calls, device starts/stops or object frees. Steady-clock calls measure render duration; these are performance probes, not physical latency measurements.

Voice admission follows the existing chronological equal-priority release-first, oldest-onset, stable-order policy. Cancelled-before-start voices have no audible retirement. Sounding stolen voices fade for 5 ms. Voices retain release tails across loop boundaries; a two-stream cycle scheduler merges strums crossing a boundary without accumulating a rounded frame error per cycle. Gain and pan retain the canonical plan and the studio's 0.85 master gain. No unannounced limiter changes authored music; clipped-sample counts are exposed for qualification.

The 64-active/64-retiring bounds apply per session. A 5 ms whole-session crossfade can briefly process both an old and new session in a lane, and transport/preview are separate lanes. Qualification must include that transition load. Final app shutdown rejects queued control work, sends a non-droppable shutdown request and joins/uninitializes the device before closing the WebView. The updater uses the same native shutdown before invoking the framework installer; an installation error re-enables control so the still-open app can continue. This is implementation, not a verified signed update.

Transport handles carry control-thread-issued ownership IDs. Cancelled or older asynchronous Play/seek/stop messages cannot replace or stop a newer session. Global stop also cancels pending Play preparation; session IDs are host state, not saved musical data. Native edits retain the current owner and cannot replace a stopped or newer transport.

Pause fades and freezes voice state/position; resume fades in the retained state. Stop fades and clears voices. Seek creates a new prepared session, reconstructs allocation history, and pre-rolls surviving voices on the control thread to preserve oscillator/filter/modulation state before a short crossfade. Long seeks can take preparation time. Hear sound publishes a separate preview session and does not stop the transport. Edits replan the current document and update the native session while playback continues.

Device changes stop the current session. Stop/reroute/interruption notifications set an atomic disconnect flag; the callback outputs silence and the UI reports the change. Refresh/select the output to reopen it; music does not resume automatically. Backend-specific notifications and real disconnect/reconnect/sleep behavior require physical qualification. Rate/buffer requests are hints; actual client/hardware rates and period information are reported. Saved named outputs are matched only when unambiguous; a missing output requires explicit selection. Native preferences remain in the existing profile, including folder-local Windows portable storage.

## Supported musical scope

Two oscillator slots (sine, triangle, square, sawtooth and 32 harmonics), existing band-limited banks, static filters, canonical envelope/note-off, prepared bend/glide curves, equal-power pan, all four v2 modulation sources/six target IDs, smoothing, and v3 filter.cutoff automation. Beat/Song onsets and strums come from audio.js's shared renderEvents resolver; instrument/sound gain uses the same resolveEvent and planSynthVoice functions as the web host.

Native noise/decay and delay/effect tails are implemented. Drive with 4x oversampling and legacy movement LFOs are implemented in execution packet v7. Sample and recorded/vocal playback are implemented in the v8 prepared voice packet. Filter sweeps use a versioned v4 execution packet; this is not a new saved Beat/Song format. Sweeps can be combined with canonical cutoff automation, but require browser/native acoustic qualification before release. Native microphone capture and count-in use the same duplex device callback as playback. WAV export and sound analysis also use native rendering. Expanding these capabilities requires independent browser/native comparisons before enabling them; no synthesis substitution or arbitrary rendering downgrade is allowed.

## Qualification

Run `npm run benchmark:device` on Linux with g++. It fetches the verified header, builds the same mixer/device layer, and records benchmarks/native-device.latest.json. 105 PCM comparisons and 12 null-backend cases cover 1/8/32/64 voices at 44.1/48/96 kHz, canonical v1/v2/v3 PCM, arbitrary block sizes, seek state, release-first stealing, loop tails, pause/resume, parallel preview, rapid play/stop and malformed packets. C++ operator-new assertions cover both the mixer and actual miniaudio callback. Existing browser/native acoustic thresholds remain unchanged (max 1e-4, RMS 2e-5).

Software callback CPU and render deadline misses are recorded with CPU/OS identity and explicit null-backend labels. They are not hardware driver underruns. Device underruns and measured physical latency are null/unmeasured. The current preview workflow runs the native device path inside the Windows portable WebView using the test backend, including upgraded/moved/copied folders. Windows portable is the only published preview edition during rapid prototyping; macOS/Linux production backend code and package configurations remain maintained for full-release qualification. Physical Windows 11 listening/microphone and real-backend device/performance checks remain pending.

Before stable: identify CPU/audio interface/driver/OS/backend; measure actual 1/8/32/64-voice behavior at 44.1/48/96 kHz, sustained playback, callback p95/max CPU, real driver underruns, external/loopback latency, rapid cycles, output switching, disconnect/reconnect and sleep/resume. Do not infer those results from headless CI. Updater key provisioning and a paired signed installation test remain separate release gates, documented in desktop-host.md; private signing keys never belong in git.

## Delay execution packet v6

The native session shares stereo feedback buses by exact authored mix/time/feedback, with the same dry (`1 - mix*.4`), send (`mix*.55`) and wet (`.8`) gains as `audio.js` and `src/hosts/web/voice-session.js`. Delay times use linear fractional-sample interpolation and AudioParam float rounding. An independent browser impulse measurement at 48 kHz with delay .07137 s observed its first echo at frames 3425/3426 and its next echo at 6978–6980, establishing the additional 128-frame feedback-cycle delay. This is an explicit compatibility choice with the existing Chromium reference, independent of native callback size. No browser audio runs in the native render path.

All bus buffers allocate on the control thread. Up to 32 buses continue after voices finish or are stolen, across note and loop boundaries. Non-loop playback waits for the conservative -100 dBFS tail bound. Pause freezes the complete effect state. Stop and session replacement fade the whole mix. Seeking pre-rolls the full relevant history on the control thread so echoes from already-ended notes are retained; long seeks can take preparation time. The portable data paths and update workflow are unchanged.

Twelve independent browser/native fixtures cover Sine Keys and fractional delay with zero, .22 and .8 feedback at 44.1/48/96 kHz. All 227 acoustic cases pass the unchanged max 1e-4 / RMS 2e-5 gates. Native mixer tests additionally cover shared buses, note endings, loop tails, seeks into ended-note echoes, block sizes 1/17/128/511/8192, and malformed v6 packets. The offline renderer now uses the device parser so validation cannot drift; v5+ noise combined with cutoff automation is also accepted correctly. These are automated software results, not physical Windows qualification.

## Complete factory synthesis (execution packet v7)

All 28 factory synth presets now prepare natively. Drive retains the existing 1024-point curve, strength rounding, compensation, and 4x oversampling: streaming two-stage polyphase sinc interpolation and decimation, shared immutable recipes and fixed per-voice histories. The same filter definitions and group delay as the Chromium reference retain the authored sound. x64 uses baseline SSE2; other platforms retain a scalar path. Third-party notices ship in the portable ZIP.

Legacy vibrato preserves its delayed entry and fade, tone adds an audio-rate cutoff LFO before octave modulation, and tremolo acts before pan/delay sends. Pitch glides and bends retain their canonical sampled curves. Integer source teardown prevents an extra LFO sample at exact boundaries. Fractional noise onsets interpolate the deterministic float noise buffer.

The expanded independent matrix covers every factory synth preset at start 0 and fractional .010123 seconds, at 44.1/48/96 kHz. All 412 acoustic cases pass the unchanged max 1e-4 / RMS 2e-5 gates. Additional native tests exercise allocation-free drive/movement at five rates from 8–192 kHz, five block sizes, note overlap, seeking and loops. Browser reference repairs initialize constant movement frequencies before starting, avoid redundant time automation that discarded fractional LFO phase, and extend the existing phase-correct silent carrier pre-roll to legacy patches. These are source-timing corrections, not tolerance changes.

## Native samples and vocals (execution packet v8)

The audio control worker decodes the existing external audio bytes using Symphonia and a statically linked Opus decoder. WAV, MP3, OGG/Vorbis, OGG/Opus, WebM/Opus and MP4/AAC fixtures are tested. Empty PCM WAV fmt extension words are normalized without touching PCM; ISO BMFF edit lists remove AAC encoder priming and preserve declared timeline duration. No AudioContext participates in native asset preparation or playback.

C++ owns immutable decoded PCM. Rate conversion runs on the control thread with a band-limited sinc filter. Callback voices retain the existing sampler zone/velocity selection, pitch-follow and transpose, note duration/one-shot behavior, attack/release, bend/glide/vibrato, tremolo, filter, 4x drive and mono/stereo pan. Multiple voices overlap. Vocal clips use their trim, gain and arrangement timing and retain higher admission priority. Projects still reference canonical relative external assets; no audio is embedded into .premidi and portable data paths are unchanged.

Prepared assets are cached by exact bytes and device rate; changing/reopening the output invalidates the generation. Sessions retain their own shared owners, so replacing a registry or retiring a session cannot free PCM still read by a callback. The current phase bounds decoded cache ownership to 512 assets/1 GiB, individual encoded files to 48 MB and decoded duration to 301 seconds. Source mono/stereo at 8–192 kHz is qualified here; wider imported-channel/rate qualification continues before final completion.

The independent matrix now has 565 passing cases, including every factory synth, every sample preset, all 122 shipped assets and every complete example. The browser graph is rendered from the original score and browser-decoded assets; native decoding and C++ session rendering are independent. Same-rate sample DSP uses max 1e-4 / RMS 2e-5; codec/rate conversion uses separately declared max .03 / RMS .002 / relative-level .03 gates. Every library item is bit-deterministic between 128/511-frame blocks. Exact-frame session completion prevents callback-size-dependent sub-threshold delay tails. Software evidence does not qualify physical WASAPI devices.

WebM timing qualification uses Chromium 156. Negative packet timestamps round CodecDelay to the segment timestamp tick before removing any remaining front delay; OpusHead pre-skip is applied once. Per-Block DiscardPadding is removed after decoding, including laced blocks and unknown-sized MediaRecorder Clusters. The original Opus fixture has a 6.5 ms delay at a 1 ms timestamp scale: the current browser discards 336 frames, not the 312 frames observed in Chromium 153. Independent native and browser output now agree at 4776 audible frames. AAC/OGG behavior and PCM thresholds are unchanged.

## Live edits and native offline rendering

Edits are debounced in the studio and serialized with pause/resume/seek. Control prepares a replacement at the same musical position, including held/released voices and feedback history from previous loop cycles. It renders ahead to a future audio-clock boundary. The callback swaps exactly at that boundary and crossfades for 5 ms; it performs no catch-up rendering, allocation, ownership destruction or locking. Missed boundaries are rejected and retried by control rather than making callback work unbounded. Tempo changes scale musical time and paused edits retain paused state. Undo/redo use the same update path.

The binary native_render command returns stereo PCM or 16-bit WAV from the same C++ Session, including native decoded assets, vocal clips and effect tails. Export assets are prepared at 44.1 kHz without opening an output device. Sound-to-synth analysis uses native mono downmix at its requested rate. The bounded control worker owns preparation and offline work; ordinary audio callbacks continue while it renders. Long exports may delay other control replies.

Standalone native/control-tests builds the production Rust control implementation with the C++ host without a WebView. It tests decoder/owned-PCM playback and real binary 44.1/48 kHz rendering. Windows portable smoke replaces OfflineAudioContext with a throwing constructor during native WAV/play/live-edit checks. Automated results remain software qualification; physical WASAPI input/output and microphone testing are pending.

## Native microphone and count-in

The explicit recording action opens the default native microphone as mono float PCM through a duplex miniaudio device. Production uses WASAPI on Windows. Device mode changes fade/pause existing lanes, join the old callback, preserve session/asset ownership and resume on the same client rate. Record completion joins capture before copying or freeing its buffer. Short recordings use a callback-frame countdown and fixed duration; Song takes start at the exact first music frame after an optional one/two-bar native count-in. The musical playhead stays fixed during count-in and pauses freeze the lead clock.

Settings → audio performance → recording offset accepts an explicitly measured 0–500 ms round-trip correction. Capture retains the offset tail, removes the corresponding initial frames and preserves take duration. The default is zero; no physical latency is inferred from buffer counts. The 28 synthetic timing cases verify software alignment and compensation, not a microphone or DAC/ADC. Permission, mode-switch gaps, drift, dropouts and calibrated delay still require physical Windows testing.

Takes save mono 16-bit WAV at at most 48 kHz, keeping five-minute captures within the existing 48 MB asset bound. New PCM vocal assets require Song v14; v8/v10/v12 remain valid and cannot silently acquire WAV recording semantics. Bytes stay outside .premidi and retain relative asset paths. Raw microphone/converted-synth previews, imported audio conversion and vocal waveform analysis use native decoding and the native preview lane. Windows portable smoke blocks browser AudioContext/MediaRecorder/HTML media playback during native workflows.
