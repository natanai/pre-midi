# Native audio milestone (preview.4)

Desktop Play and Hear sound default to C++ synthesis in miniaudio's playback callback. The browser version retains Web Audio. Settings offers an explicit Web Audio mode for projects outside the native feature set. The existing studio, canonical parameter IDs, project formats and saved data paths are preserved. Choose Init, Triangle Keys, Touch Keys, Harmonic Keys, Sub Bass, Square Bass or Square Lead to test native output. The original Sine Keys default includes delay and requires Web Audio until native delay parity is implemented.

## Device boundary

miniaudio 0.11.25 is pinned by immutable commit and SHA-256 in scripts/fetch-miniaudio.mjs. Its device-only C API avoids a UI rewrite and hosts the existing framework-neutral C++17 Voice. We choose upstream's MIT-0 licence. JUCE adds an unnecessary application framework/licensing surface; CPAL would add a second native audio abstraction around the existing C++ core. native/host-comparison.json records the decision and distinguishes measured software callbacks from unmeasured physical backends.

Production selects WASAPI (Windows), CoreAudio (macOS), PulseAudio/ALSA (Linux), never a null/silent fallback. Device open failures are errors. The explicit test host flag selects miniaudio's null backend; desktop smoke additionally requires PREMIDI_SMOKE_OUTPUT. Its results always identify a test backend and cannot qualify hardware.

Windows Rust and C++ builds statically link the Visual C++ runtime, and CI inspects the PE dependencies to reject MSVCP/VCRUNTIME/CONCRT DLL requirements in the portable executable. WebView2 and Windows system components remain OS dependencies. C++ exception unwinding is enabled for control-side validation; Windows min/max macros are excluded at the native boundary.

Tauri's native_audio command sends requests through an eight-message bounded queue to one dedicated audio control thread. C API initialization, configuration, preparation and destruction stay on that thread, preserving backend/COM affinity. Blocking IPC workers wait for replies; the audio callback never touches the Rust queue. Shared native JS encoding carries the existing pre-midi-synth-voice v1/v2/v3 contract plus the backward-compatible v4 filter-sweep execution packet in a bounded little-endian transport; this is not a new project/music format. Native packet validation independently checks counts, finite values, rates, routes, wave IDs and time bounds.

## Real-time ownership

Parsing, JSON, allocation, wave-bank FFTs, initial filter coefficients and modulation smoothing coefficients are control work. Published sessions own immutable plans and tables plus fixed-size callback state. Separate transport and preview lanes each have 64 logical voices and 64 retiring voices. Each lane has three control-owned session slots: active, fading predecessor and pending. The callback publishes the new active pointer before clearing pending; control reads pending before active/retiring and never frees a visible pointer. C++ atomic counters, controls and pointers are statically required to be lock-free.

The callback mixes blocks of at most 128 frames. Device callbacks above 8192 frames are silenced and counted instead of allowing unbounded synth work. Each lane has a 256-onset callback budget; preparation rejects excess onset density, more than 4096 notes per cycle, more than 32 unique banks, packets above 16 MiB, voices beyond 30 seconds or sessions beyond 10 minutes. Retirement-capacity/onset faults stop the session and are reported; unsupported density never silently drops notes. There are no callback heap allocations, locks, files, JSON parsing, UI calls, device starts/stops or object frees. Steady-clock calls measure render duration; these are performance probes, not physical latency measurements.

Voice admission follows the existing chronological equal-priority release-first, oldest-onset, stable-order policy. Cancelled-before-start voices have no audible retirement. Sounding stolen voices fade for 5 ms. Voices retain release tails across loop boundaries; a two-stream cycle scheduler merges strums crossing a boundary without accumulating a rounded frame error per cycle. Gain and pan retain the canonical plan and the studio's 0.85 master gain. No unannounced limiter changes authored music; clipped-sample counts are exposed for qualification.

The 64-active/64-retiring bounds apply per session. A 5 ms whole-session crossfade can briefly process both an old and new session in a lane, and transport/preview are separate lanes. Qualification must include that transition load. Final app shutdown rejects queued control work, sends a non-droppable shutdown request and joins/uninitializes the device before closing the WebView. The updater uses the same native shutdown before invoking the framework installer; an installation error re-enables control so the still-open app can continue. This is implementation, not a verified signed update.

Transport handles carry control-thread-issued ownership IDs. Cancelled or older asynchronous Play/seek/stop messages cannot replace or stop a newer session. Global stop also cancels pending Play preparation; session IDs are host state, not saved musical data. A native edit displays a short restart reminder because this milestone plays an immutable snapshot.

Pause fades and freezes voice state/position; resume fades in the retained state. Stop fades and clears voices. Seek creates a new prepared session, reconstructs allocation history, and pre-rolls surviving voices on the control thread to preserve oscillator/filter/modulation state before a short crossfade. Long seeks can take preparation time. Hear sound publishes a separate preview session and does not stop the transport. Native playback snapshots the document at Play; live edit/replanning remains a subsequent milestone, disclosed in Settings and release notes.

Device changes stop the current session. Stop/reroute/interruption notifications set an atomic disconnect flag; the callback outputs silence and the UI reports the change. Refresh/select the output to reopen it; music does not resume automatically. Backend-specific notifications and real disconnect/reconnect/sleep behavior require physical qualification. Rate/buffer requests are hints; actual client/hardware rates and period information are reported. Saved named outputs are matched only when unambiguous; a missing output requires explicit selection. Native preferences remain in the existing profile, including folder-local Windows portable storage.

## Supported musical scope

Two oscillator slots (sine, triangle, square, sawtooth and 32 harmonics), existing band-limited banks, static filters, canonical envelope/note-off, prepared bend/glide curves, equal-power pan, all four v2 modulation sources/six target IDs, smoothing, and v3 filter.cutoff automation. Beat/Song onsets and strums come from audio.js's shared renderEvents resolver; instrument/sound gain uses the same resolveEvent and planSynthVoice functions as the web host.

Native noise, drive/oversampling, delay/effect tails, legacy movement LFOs, samples and recording/vocal playback remain explicit errors. Filter sweeps use a versioned v4 execution packet; this is not a new saved Beat/Song format. Sweeps can be combined with canonical cutoff automation, but require browser/native acoustic qualification before release. No native microphone input or Song capture alignment is claimed. WAV export and recording retain Web Audio. Expanding these capabilities requires independent browser/native comparisons before enabling them; no synthesis substitution or arbitrary rendering downgrade is allowed.

## Qualification

Run `npm run benchmark:device` on Linux with g++. It fetches the verified header, builds the same mixer/device layer, and records benchmarks/native-device.latest.json. Cases cover 1/8/32/64 voices at 44.1/48/96 kHz, canonical v1/v2/v3 PCM, arbitrary block sizes, seek state, release-first stealing, loop tails, pause/resume, parallel preview, rapid play/stop and malformed packets. C++ operator-new assertions cover both the mixer and actual miniaudio callback. Existing browser/native acoustic thresholds remain unchanged (max 1e-4, RMS 2e-5).

Software callback CPU and render deadline misses are recorded with CPU/OS identity and explicit null-backend labels. They are not hardware driver underruns. Device underruns and measured physical latency are null/unmeasured. The current preview workflow runs the native device path inside the Windows portable WebView using the test backend, including upgraded/moved/copied folders. Windows portable is the only published preview edition during rapid prototyping; macOS/Linux production backend code and package configurations remain maintained for full-release qualification. Physical Windows 11 listening/microphone and real-backend device/performance checks remain pending.

Before stable: identify CPU/audio interface/driver/OS/backend; measure actual 1/8/32/64-voice behavior at 44.1/48/96 kHz, sustained playback, callback p95/max CPU, real driver underruns, external/loopback latency, rapid cycles, output switching, disconnect/reconnect and sleep/resume. Do not infer those results from headless CI. Updater key provisioning and a paired signed installation test remain separate release gates, documented in desktop-host.md; private signing keys never belong in git.
