# Native audio playback

## Classic modulation effects (2026-11-10)

Source now implements chorus, flanger, phaser and auto-pan in the shared `chain.post` order after articulation/stereo/pan and before dry/echo/room sends. Four post processors total, including dynamics, share the eight-active-processor limit. All have independent note/Clip state, bypass/mix/reorder/remove/restore, project/preset/source reuse and the common Inspector's numerical/direct illustrations. These changes are not in published Windows preview.31.

Chorus/flanger use sinusoidally moving stereo fractional delay lines with linear interpolation; chorus delay is 5–40 ms and depth 0–12 ms, flanger delay 0.2–10 ms and depth 0–5 ms. Delay is clamped to 1 sample–60 ms. Signed feedback is bounded to ±0.8 and writes `(1 − |g|) × input + g × wet`. Linear interpolation softens high frequencies; extreme fast delay movement is a creative resampling effect, not a band-limited pitch processor. See Julius O. Smith's [time-varying delay effects](https://www.dsprelated.com/freebooks/pasp/Time_Varying_Delay_Effects.html).

The phaser uses six first-order all-pass sections per channel, with `a = (tan(πf/rate) − 1)/(tan(πf/rate) + 1)` and a normalized lattice: `y = a × x + b × state`, `state = b × x − a × state`, `b = sqrt(1 − a²)`. Each frozen section has `(a + z⁻¹)/(1 + a z⁻¹)`, as in Smith's [phasing reference](https://www.dsprelated.com/freebooks/pasp/Virtual_Analog_Example_Phasing.html). The section matrix is orthogonal; interpolating adjacent prepared matrices is contractive, keeping moving sections passive. Center is 50–8,000 Hz, depth 0–4 octaves, and swept frequency is clamped to 20 Hz–0.45×rate. Feedback uses the previous wet sample with the same ±0.8 bound/input normalization. This bounds energy, not instantaneous peaks; processing/mixing still needs headroom. Auto-pan balances existing left/right channels with `sqrt(2) × cos/sin((pan + 1)π/4)`; zero depth is transparent and maximum channel gain is sqrt(2).

Free rate is 0.01–20 Hz. Musical divisions use the existing `modulationRate` clock; DSP receives resolved Hz while saved free-rate/sync values stay authored. Phase and stereo offset are cycle fractions. Notes/Clips restart at authored phase, and seeks reconstruct original-age state. Free-running LFOs and effect-parameter automation remain separate roadmap work. Native immutable 1,024-point coefficient/phase tables are prepared/deduplicated on control, then interpolated without per-sample trigonometry. Optional delay storage is preallocated for 64 active plus 64 retiring voices and four post slots, about 11.3 MiB at 48 kHz or 45.1 MiB at 192 kHz. Age guards avoid clearing large rings during callback admission; retiring voices keep independent borrowed storage.

There is no additional fixed block latency. Serial effect tails add to `graphEnd`; source end/envelope timing is unchanged, and the longest echo/room send tail follows. Delay reservation is `(min(.06, delay + depth) + .00025) × (1 + ceil(log(1e-7)/log(|feedback|))) + .02` seconds, taking zero repeats at zero feedback. Phaser reservation is `max(.1, 7 × ln(1e6)/(2π × clamp(frequency/2^depth,20,1000) × (1 − |feedback|))) + .02`. Auto-pan adds no tail. Tails continue to consume the existing voice budget. WAV rendering, cached vocal seeks and page-resource pinning use the same policy. Source intervals retain existing 600-second/render bounds; prepared voice graph lifetime allows 625 seconds for release/serial tails.

Sample execution v22 carries post tags 0–3 for compressor/gate/limiter/de-esser and 4–7 for chorus/flanger/phaser/auto-pan. A modulation tag carries eight doubles: resolved rate, depth, phase, stereo, feedback, delay, frequency and mix. Room doubles follow. Streaming declares optional post-delay storage independently of tone graph state before publication. The single browser post worklet executes the same ordered recipes; native playback uses C++ only. Pause/Stop remain downstream of effects and bypass preparation queues.

Focused checks: `tests/modulationEffects.test.js` (independent pan, impulse and stationary all-pass/feedback oracles; extreme tails), `.audio.mjs` (native/worklet sources/order/overlap/seek/loop/page/block/sync/send checks), `.dom.mjs` (shared control/history/combined view) and `native/modulation-effects-test.cpp` (poisoned ring reuse/retiring ownership). Seven production Rust control tests and the 48 kHz null-device stream with chorus/phaser/dynamics/parallel routing pass with zero callback allocations. Physical Windows, listening, ring/frequency shifting and broader SE-12/M3 completion remain open. A hard-cut recording at a fractional EOF still has a pre-existing final-sample interpolation difference between native clamping and the offline browser reference; modulation phase comparisons use two silent EOF frames to isolate effect clocks.

## Shared reverb milestone

`reverb` is one optional current block (mix, preDelay, decay, damping, size, width) shared by synth, sampled Sound and vocal processing. Four damped feedback combs feed two true allpasses per stereo channel, following [Schroeder, JAES 10(3), 1962, pp. 219–223](https://aes.org/publications/elibrary/elibrary-page/?id=849). This is an original bounded implementation of that topology, not a commercial-room equivalence claim. Pre-delay is 0–200 ms; decay is nominal undamped-comb RT60, 0.2–6 s. Damping lowers feedback bandwidth; size scales delay lengths; width folds/spreads the mono-excited room's decorrelated stereo tail. Full-wet anti-phase input cancels in the mono room excitation. Dry stereo is retained according to mix. Room gain is `mix × .8`; dry is `(1 − delayMix × .4) × (1 − roomMix)`. It is not a peak limiter.

Echo and room are parallel sends, sharing a bus only when the complete authored recipe matches (32 recipes maximum). Reverb is bypassable without erasing settings. The three shared Inspector modules provide dials and direct two-axis editing; their decay plots are educational references, not measured room responses. Native ring buffers and recipes are allocated on control; the callback performs fixed PCM work only. The browser uses the matching AudioWorklet kernel and the same audio-time stop/retirement gate. Native playback never loads browser audio.

Room tail reservation is `preDelay + 3 × decay + .5` seconds, combined with echo by maximum, not sum. Seeks warm prior source history, including completed vocal Clips; loops preserve the shared room state. Page resources stay pinned through their complete effect lifetime. Preview, Beat/Song playback and WAV export use this policy, with existing render limits. Processing remains editable; source assets are untouched. The current sample execution packet is v22 and contains six independently validated room doubles after ordered post processors; no older packet reader is retained. The streaming control action is `stream_effects`, registering the complete wet recipe before page one.

Focused tests: `tests/reverb.test.js`, `tests/reverb.audio.mjs`, shared `tests/dynamics.dom.mjs`, compiled Rust control tests and the 48 kHz null-device streaming check with room/dynamics/parallel routing. Native/worklet PCM maximum difference was 3.725290298461914e-9 at 24 kHz; callback allocations were zero. Windows preview.31 is published with these changes; Windows compilation, 14 Rust tests and portable-folder checks passed. Physical Windows and matched listening remain user acceptance work.

## Sound dynamics milestone

`chain.post` orders up to four compressor, gate, de-esser or limiter instances after source articulation/level, stereo imaging and pan, before dry/echo sends. It references the same stable instance IDs, parameters, bypass and mix data as the tone chain, with eight active processors total. Presets and synth/sample/vocal reuse retain it. The shared Inspector supplies dials, transfer and gain-response illustrations, history and both panel views. These illustrations show reference behavior, not measured playback meters.

Each native Voice owns four fixed detector states; control parses and prepares the immutable recipes. The detector uses the maximum absolute stereo channel sample and applies one linked gain to both channels. Compressor gain uses a feed-forward dB transfer with optional quadratic soft knee. Attack/release are exponential dB-gain time constants. Gate starts closed, opens with attack, holds after the last above-threshold sample, then closes with release to its finite range. Limiter attack is immediate, with release smoothing and a final linked sample-peak gain bound. There is zero lookahead and no added block latency. Full-wet limiting bounds each note/Clip's output; parallel dry mix, overlapping voices and echo returns can exceed that ceiling. This is not master or true-peak protection.

The de-esser detects the maximum absolute channel level after an [RBJ constant-0-db-peak bandpass](https://www.w3.org/TR/audio-eq-cookbook/) with BLT-corrected octave bandwidth. It subtracts only the selected band by the smoothed linked reduction: output = input + band × (gain − 1). Threshold controls onset; amount limits reduction to 0–24 db. Center frequency is 1–14 khz, clamped to 0.45 × sample rate; bandwidth is 0.1–3 octaves. It has no external sidechain, lookahead or independent tail. Filter state stops at the existing voice/Clip graph boundary. It is not a peak guard; time-varying processing and the final mix still need headroom. The three shared illustrations show the maximum-cut response at 48 khz, the selected-band transfer and a gain-step reference; they are not live analyzers.

Browser playback uses an AudioWorklet with the matching numerical kernel and no UI-timer DSP. Real-time contexts prepare it once for live edits; offline renders load it only for active post processors. The Pages dependency closure includes its versioned module and worker dependency. Native playback never creates a browser audio context. Voice/Clip state stays independent, seeks reconstruct history and loops start new voice states. Dynamics-only browser vocal seeks use the existing bounded continuation cache. Dynamics adds no effect tail.

Current sample execution is packet v22. Its bounded dynamics trailer is validated independently in C++; callbacks only execute prepared values. Focused checks in `tests/dynamics.*`, `native/dynamics-test.cpp` and the 48 kHz null-device stream exercise model recall, direct editing/history, native/worklet PCM, ordering, overlap isolation, seeking/looping/page clocks, live revisions and capture, with zero native callback allocations. Physical Windows, observed listening and a new portable package remain unqualified. External sidechain selection, shared buses, measured gain-reduction feedback and dynamics parameter automation remain in SE-10/SE-07. Dynamics mode 3 adds three validated doubles (frequency, bandwidth, amount) to its recipe; project file versions are unchanged.

## Device boundary

miniaudio 0.11.25 is pinned by immutable commit and SHA-256 in scripts/fetch-miniaudio.mjs. Its device-only C API avoids a UI rewrite and hosts the existing framework-neutral C++17 Voice. We choose upstream's MIT-0 licence. JUCE adds an unnecessary application framework/licensing surface; CPAL would add a second native audio abstraction around the existing C++ core. native/host-comparison.json records the decision and distinguishes measured software callbacks from unmeasured physical backends.

Production selects WASAPI (Windows), CoreAudio (macOS), PulseAudio/ALSA (Linux), never a null/silent fallback. Device open failures are errors. The explicit test host flag selects miniaudio's null backend; desktop smoke additionally requires PREMIDI_SMOKE_OUTPUT. Its results always identify a test backend and cannot qualify hardware.

Windows Rust and C++ builds statically link the Visual C++ runtime, and CI inspects the PE dependencies to reject MSVCP/VCRUNTIME/CONCRT DLL requirements in the portable executable. WebView2 and Windows system components remain OS dependencies. C++ exception unwinding is enabled for control-side validation; Windows min/max macros are excluded at the native boundary.

Tauri's native_audio command sends requests through an eight-message bounded queue to one dedicated audio control thread. C API initialization, configuration, preparation and destruction stay on that thread, preserving backend/COM affinity. Blocking IPC workers wait for replies; the audio callback never touches the Rust queue. Shared native JS encoding carries the existing pre-midi-synth-voice v1/v2/v3 contract plus backward-compatible v4 filter sweep, v5 noise, and v6 delay execution packets in a bounded little-endian transport; this is not a new project/music format. Native packet validation independently checks counts, finite values, rates, routes, wave IDs and time bounds.

## Real-time ownership

Parsing, JSON, allocation, wave-bank FFTs, initial filter coefficients and modulation smoothing coefficients are control work. Published sessions own immutable plans and tables plus fixed-size callback state. Separate transport and preview lanes each have 64 logical voices and 64 retiring voices. Each lane has three control-owned session slots: active, fading predecessor and pending. The callback publishes the new active pointer before clearing pending; control reads pending before active/retiring and never frees a visible pointer. C++ atomic counters, controls and pointers are statically required to be lock-free.

The callback mixes blocks of at most 128 frames. Device callbacks above 8192 frames are silenced and counted instead of allowing unbounded synth work. Each lane has a 256-onset callback budget; preparation rejects excess onset density, more than 4096 notes per cycle, more than 32 unique banks, packets above 16 MiB, voices beyond 30 seconds or sessions beyond 10 minutes. Retirement-capacity/onset faults stop the session and are reported; unsupported density never silently drops notes. There are no callback heap allocations, locks, files, JSON parsing, UI calls, device starts/stops or object frees. Steady-clock calls measure render duration; these are performance probes, not physical latency measurements.

Voice admission follows the existing chronological equal-priority release-first, oldest-onset, stable-order policy. Cancelled-before-start voices have no audible retirement. Sounding stolen voices fade for 5 ms. Voices retain release tails across loop boundaries; a two-stream cycle scheduler merges strums crossing a boundary without accumulating a rounded frame error per cycle. Gain and pan retain the canonical plan and the studio's 0.85 master gain. No unannounced limiter changes authored music; clipped-sample counts are exposed for qualification.

The 64-active/64-retiring bounds apply per session. A 5 ms whole-session crossfade can briefly process both an old and new session in a lane, and transport/preview are separate lanes. Qualification must include that transition load. Final app shutdown rejects queued control work, sends a non-droppable shutdown request and joins/uninitializes the device before closing the WebView. The updater uses the same native shutdown before invoking the framework installer; an installation error re-enables control so the still-open app can continue. This is implementation, not a verified signed update.

Transport handles carry control-thread-issued ownership IDs. Cancelled or older asynchronous Play/seek/stop messages cannot replace or stop a newer session. Global stop also cancels pending Play preparation; session IDs are host state, not saved musical data. Native edits retain the current owner and cannot replace a stopped or newer transport.

Pause fades and freezes voice state/position; resume fades in the retained state. Stop fades and clears voices. Seek creates a new prepared session, reconstructs allocation history, and pre-rolls surviving voices on the control thread to preserve oscillator/filter/modulation state before a short crossfade. Long seeks can take preparation time. Hear sound publishes a separate preview session and does not stop the transport. Edits replan the current document and update the native session while playback continues.

Device changes stop the current session. Stop/reroute/interruption notifications set an atomic disconnect flag; the callback outputs silence and the UI reports the change. Refresh/select the output to reopen it; music does not resume automatically. Backend-specific notifications and real disconnect/reconnect/sleep behavior require physical qualification. Rate/buffer requests are hints; actual client/hardware rates and period information are reported. Saved named outputs are matched only when unambiguous; a missing output requires explicit selection. Native preferences remain in the existing profile, including folder-local Windows portable storage.

The native decoder accepts 1–32-channel PCM/IEEE-float RIFF WAV at 8–192 kHz, including 24/32-bit PCM and extensible WAV formats. Multistream Opus supports 3–8 channels with explicit channel ordering. Decoding, owned PCM, sample-rate conversion and filter preparation occur on the control thread; only prepared PCM and fixed per-channel DSP histories reach the callback. The existing stereo downmix and factory sample/synth behavior are unchanged.

PR #63 passed the full browser/native acoustic matrix, Rust control/decoder tests and Windows portable packaging/upgrade checks with unchanged comparison gates. Experimental multichannel AAC/HE-AAC priming, Vorbis duration and 384–768 kHz imports remain in unmerged draft PR #62. These import capabilities do not alter Beat/Song .premidi schemas or embed audio assets into documents. No physical WASAPI latency qualification is claimed.
