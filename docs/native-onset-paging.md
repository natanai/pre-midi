# Native Song onset paging: implementation and qualification contract

Status: **bounded page compilation, real dynamic C++ Voice/sample ingestion (#187), cross-page delayed-onset/shared-effect continuity (#189), payload transport binder (#191), and miniaudio null-device C ABI/Rust actions (#192) verified. Experimental JS source/ACK feeder exists behind a developer-only opt-in, but default end-user Song streaming, full edit/seek/loop/capture lifecycle and physical Windows 11 acceptance remain open.**

For the current exact-build, open-PR cleanup, release decision and remaining JS/Rust/device acceptance work, use [Song stabilization and handoff (2026-11-05)](song-stabilization-handoff-2026-11-05.md). The older preparation-only sections below are preserved as implementation history; #187/#189/#191 supersede the "not yet implemented" portions for the internal C++ mixer.

Canonical Song/freeform completion and ordering: [song-rollout.md](song-rollout.md).

## Implemented control-thread preparation

- `songSchedule.js → scheduledSongOnsetsInWindow(song,startStep,endStep,{maxEvents})` compiles only authored onsets in the half-open absolute Song-step range. It preserves Beat source phase, non-bar-aligned Clips, repeated freeform Chunks, direct notes, vocal onsets, original note duration and source references. It does not enumerate all earlier repetitions to fetch a late window. The maximum returned count is bounded by 4,096.
- `src/hosts/native/onset-pages.js → nextNativeOnsetPage(song,startStep,{maxSteps,maxOnsets})` chooses the longest whole-step window inside both limits, using a monotonic search of source-linked onsets. A step containing more events than its budget is rejected explicitly rather than silently partitioned, shortened or dropped.
- The unit fixtures compare every compiled window with the original full Song onset schedule, including long note releases across page edges, order/phase, large sparse Songs, high density, and non-destructive source ownership. These tests do **not** verify real-time callback page delivery.

## C++ control/callback page mailbox (experimental milestone)

- [PR #177](https://github.com/natanai/pre-midi/pull/177) introduces `native/page-mailbox.hpp` and a standalone C++17 test in `native/page-mailbox-test.cpp`, run from the source-verification workflow with `scripts/native-page-mailbox-check.mjs`. PR #177 passed full browser/native CI and Windows Server 2022 portable-build qualification and merged into `main`. This is a metadata-only control/callback mailbox, **not a playable packet scheduler**.
- The mailbox has three fixed slots and immutable owner/revision/sequence/absolute-frame descriptors. The producer validates a contiguous timeline, a maximum of 4,096 events and 512 declared resource references, and publishes with release semantics. The callback acquires a ready slot at an exact boundary without allocating or waiting, acknowledges sequence and end frame, and retires old slots for control-thread reclamation.
- A missing, late or stale page is fatal rather than disguised as successful silence. Stop/edit/revision invalidation needs a new mailbox. The standalone test measures callback allocations, owner/revision rejection, terminal handling, bounded backpressure and real two-thread order; it does not run native synth voices across a page edge.
- [PR #179](https://github.com/natanai/pre-midi/pull/179) merged after full CI: `renderEventsInWindow` uses exactly the same event materialization as full Song playback, including source-phase cutoff automation, vocal references and strum offsets across page boundaries. It does **not** replace the existing single-session native transport.
- [PR #180](https://github.com/natanai/pre-midi/pull/180) merged after the complete browser/native CI suite passed. `nativePageDescriptorCursor` maps absolute Song steps into monotonically sequenced native audio frames with a **mandatory** edit-revision reader; descriptors remain `prepared:false` until actual resources are resolved and pinned. This is metadata preparation, not playable paging.
- [PR #183](https://github.com/natanai/pre-midi/pull/183) merged after full Chrome/native CI and Windows Server 2022 portable-build checks. `native/paged-mixer-probe.hpp` exercises the **actual existing C++ Session mixer** across non-block-aligned page boundaries, with a callback-sized lookahead producer. Native PCM matches uninterrupted Session playback at 44.1/48/96 kHz, including delay feedback and stereo sample lifetime. This is a **test-only page clock**; every note is still preloaded in the same bounded Session.
- [PR #184](https://github.com/natanai/pre-midi/pull/184) merged after complete CI. `src/hosts/native/page-plan.js` converts synth/sample/vocal time coordinates to page-local seconds anchored to exact native `startFrame`, retaining absolute sample-frame alignment even after 600 seconds. `scripts/native-page-plan-check.mjs` confirms C++ synth/filter, sample and vocal PCM equivalence after rebasing. Current native playback continues to reject unpaged >600-second voices.
- [PR #185](https://github.com/natanai/pre-midi/pull/185) merged after complete Chrome/native and Windows Server 2022 checks. `native/prepared-page.hpp` validates **real** native PMS1/PMS2 voice packets using the existing C++ `Session` parser/preparer, verifies event counts/asset pointers/resource budgets and constructs a `prepared:true` descriptor only after actual oscillator banks, DriveRecipes, LFO tables, sample PCM and delay recipes are owned. The `PreparedPageLease` computes a conservative resource hold frame that includes source notes and effect tails; native callback tests continue rendering an existing Voice after the mailbox metadata has retired, with zero callback allocation. This is a **control-thread-only resource backing**, not the persistent mixer or a dynamic payload-to-callback binder.
- **Crucial resource-lifetime distinction:** a page’s descriptor may be retired at its end frame, but its banks/samples/plan data must **not** be freed merely because that metadata slot was reclaimed. A strummed onset authored in page A can sound after page B begins, and an already-sounding oscillator or recorded sample may release several pages later. The future Session needs independent resource lifetime ownership until every delayed onset, active Voice and effects tail has ended.
- A whole-Session replacement/crossfade is not a valid shortcut: existing `native/session.hpp` keeps oscillator banks, DriveRecipes, sample channels, active Voice objects and delay feedback within one Session. Swapping whole Sessions does not retain their exact DSP state or shared voice-stealing policy.
- Before wiring the mailbox into the real audio device, connect descriptors to fully prepared and pinned C++ packet/bank/sample/effect resources; the callback must not accept a Boolean “prepared” claim without validating actual immutable resource handles. The Session must keep active voices, delay and modulation state alive across page consumption.

## Existing native safety invariants (still mandatory)

`src/hosts/native/session.js` and `native/session.hpp` currently accept one immutable C++ Session for a playback cycle of at most 600 seconds and at most 4,096 note/voice onsets, subject to a 16 MiB encoded event-packet cap, per-render-block onset density, voice limits, and bounded oscillator/delay recipes. Playback over either limit must fail preflight explicitly; **never** silently route to Web Audio or increase constants as a shortcut.

Window compilation alone does not bypass the single-session limit or make long Songs playable. Every window is still an unplayed preparation artifact until the remaining steps below have shipped.

## JavaScript source-linked page publication milestone (staged, not enabled)

`src/hosts/native/song-stream-page.js` now builds bounded, immutable native Song packets from the existing `renderEventsInWindow`, `nativePageDescriptorCursor`, `nativePlans` and frame-accurate `rebaseNativePlansToPage` functions. It also inventories shared synth/vocal delay recipes before the real-time stream begins and provides a revision-bound publisher that retries an identical packet when the Rust/C++ mailbox returns `accepted:false`. Failed assets, changed revisions, unregistered delay recipes, mismatched event counts and malformed ACK responses reject before further publication. `tests/nativeSongStreamPage.test.js` covers late (>600 s) rebasing, cross-platform effect precision, backpressure and failure ownership.

**The source/packet layer is now exercised by an explicitly opted-in Tauri preview bridge, not by the default shipping Song player.** `audio.js::play` routes to `src/hosts/native/song-stream-control.js` only when the local developer flag `premidi-native-song-streaming=experimental` is set. The bridge performs owner/revision-bound begin → shared delay registration → three-page preload → native start, ACK-based lookahead, bounded backpressure retry, pause/resume, fault reporting and stop. Its tests use a simulated Rust action interface, not physical hardware. The default native path is unchanged. **Still open:** full revision-safe live edit/seek/loop reconstruction, microphone handoff, real-device queue starvation/fault recovery, physical WASAPI output and exported-project parity. The experimental bridge rejects unqualified features visibly and stops transport; it must not be offered as stable end-user functionality. The normal 600-second/4,096-onset preflight remains in force. Treat this as a checked intermediate engineering milestone, not end-user long-Song playback or permission to publish a new stable release.

## Required native host protocol before enabling pages

1. A control worker prepares immutable absolute Song-time event pages, voice-bank recipes, external WAV/recording handles, and effect resources before publication. Page duration adapts to onset density *and* measured bank, effect, audio asset and callback work capacity. The audio callback must not parse packets, allocate memory, decode files, lock a mutex, or wait for page delivery.
2. The C++ host exposes an owner- and revision-bound **publish / acknowledge** protocol with bounded pending and active slots. Each page includes its absolute frame interval, revision, monotonic sequence number, and a complete, validated resource handle set. The real-time callback acknowledges exactly when a page becomes active and reports underrun/fault conditions without invoking host JS.
3. Preserve live oscillator phases, envelope/release state, vibrato/pitch and cutoff automation phase, active sample/recording playback positions, distortion/filter history and delay feedback across a page boundary. A note with onset in page A but release in page B is started **only in A**. Do not create a second Voice in B or truncate the first. Preserve deliberate polyphony and overlapping vocals.
4. Seek, pause/resume, stop, loop and Song edits need deterministic page invalidation and transport ownership. A seek reconstructs every still-sounding note and effect at its exact absolute source phase; a loop does not reuse stale revision pages. Changes should invalidate future pages while protecting callback-owned resources still in use. An unloaded page must lead to a clear native fault/stop, never a timing gap disguised as success.
5. Audit samples and presets using their existing `.premidi` and folder-local asset references. There is no separate sample format, alternate synth, or second Song clock. Page transport remains a native C++ playback concern; educational Sound illustration code and phone UI are outside this milestone.

## Historical implementation patch boundaries (steps 1–3 completed; step 4 still open)

The numbered descriptions retain their original design contract. #187 implemented persistent C++ ingestion, #191 bound actual page resources, and #192 connected miniaudio callbacks and Rust actions. **Do not treat steps 1–3 as active blockers.** The JS feeder, lifecycle and physical Windows tests remain open.

1. **Implemented in #187/#189: `native/session.hpp`: stateful page consumer.** Keep one persistent mixer clock, active/retiring `Slot::voice` arrays, `SampleChannelState`, oscillator phases, modulation/filter history and `Bus::delay` state for the entire Song. Consume newly prepared `PreparedNote` onset pages in exact source order using the mailbox's frame boundary and acknowledgment. A whole-Session crossfade via `Lane::publish()` is not equivalent, because it resets or duplicates active DSP state. Split callbacks at page boundaries without allocating, waiting or reparsing packets.
2. **Implemented in #191: bind prepared resources to active page payloads.** PR #185 now provides independently validated `PreparedPageLease` objects with the original DSP parser and a resource-retention horizon. **Historical missing work, delivered in #191:** a bounded, sequence-owned C++ slot carrying the real lease from the control thread into a persistent audio Session; a no-allocation callback view of the matching `PreparedNote` instructions; control-thread retirement only after every strummed delayed onset, active/releasing Voice and delay tail is finished. Metadata ACK by itself must never destroy resources. Coordinate registered sample/recording handles and global/shared delay bus recipes with the lifetime of the one persistent mixer.
3. **Implemented in #192: `native/device-host.h/.cpp` plus `desktop/src/audio/control.rs`: revision-owned host bridge.** Add explicit transport start, publish, acknowledgment/status, invalidate and stop operations for stateful pages using the existing Rust `owner:u64` permissions and a monotonic Song edit revision. Validate resource/packet binding before setting descriptor `prepared:true`; require exact expected sequence and absolute `startFrame`. An underrun or stale edit must surface as a native fault rather than inventing silence or silently switching engines.
4. **Still open: `src/hosts/native/session.js`, `src/hosts/native/onset-pages.js`, `audio.js`: lookahead feeder.** Compile only the next bounded Song window with `nextNativeOnsetPage`, `renderEventsInWindow` and the revision-owned `nativePageDescriptorCursor` once the associated PR is qualified. Prepare native assets/control-side voice plans, retain the source Song clock and wait for the host ACK before retiring page metadata. On tempo change, seek, undo/redo, loop, output-device change or failure, invalidate outstanding pages without deleting user music.
5. **No premature release claims.** Keep the existing `playNative` and C++ `Session` 600-second/4,096-onset refusal paths untouched until actual paged PCM equivalence and failure-handling tests pass. Browser and WAV/export limits must be reconsidered and independently qualified; a new portable Windows ZIP must be tested from the exact resulting commit.

## Qualification to remove the old limits

- Equivalence between full and paged source-linked onsets at 4,095/4,096/4,097 event boundaries, high-density multi-Clip overlaps, mixed pitched/Rack Sounds, irregular Chunks, independent notes, vocals, sample zones and recorded takes.
- Deterministic native-vs-browser PCM and timeline fixtures spanning multiple pages: sustain/release, oscillators, cutoff/pitch modulation, filter/distortion state, delay feedback, recording trim/offset, edit/undo/redo, seek and loop.
- A 10+ minute sparse Song, prolonged silence between pages, callback starvation, forced page rejection, stale revision/owner, memory/bank limits, device loss and clean recovery. Record callback allocations and worst-case processing time.
- Windows CI qualification, then actual Windows 11 device output, recording latency/listening, portable folder relocation and `.premidi`/WAV export acceptance. A tested portable ZIP must be built from the exact qualified commit.

**Stop condition:** If any page has unresolvable dependencies, a missing handle, a non-finite transport duration, an impossible callback budget, or a failed acknowledgment, native playback must stop with a diagnostic without losing the authored Song or changing its music.
