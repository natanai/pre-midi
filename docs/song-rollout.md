> **Current source checkpoint, 2026-11-10:** Tauri/Rust hosts the studio and C++17/miniaudio executes native playback, capture and WAV rendering. Experimental Song streaming now implements seek, loop, live edits, count-in and synchronized recording; it remains opt-in while normal playback retains its 600-second/4,096-onset limits. Shared compressor/gate/limiter, split-band de-essing and algorithmic reverb are implemented through the common Inspector. Pause/resume bypass preparation queues and owned Stop gates the callback, with transport ownership and blocked-worker regressions. Chorus/flanger/phaser/auto-pan are now implemented in the same native/browser post-processing path with tempo sync, original-age state, interactive controls and bounded tails. Ring modulation, frequency shifting and independent recorded-source pitch/time/formants/reverse now join them for requested preview.32. Broader automation/routing, sampler loops, tuning and physical acceptance remain open. Published preview.31 includes the preceding dynamics/reverb/transport milestones and passed automated Windows/portable checks; physical Windows qualification remains open. The active task scope and remaining production effects are recorded in [synthesis-roadmap.json](synthesis-roadmap.json) and [native-audio.md](native-audio.md). **No current overall completion percentage is established.** Historical checkpoints below do not override this summary.

Status: **Stage 5 (vocal recording) implemented, reliability work ongoing**. Stage 6 (pre-programmed native parity) has not shipped.

## Approved attached freeform architecture (2026-11-04)

**Desktop and Windows native first (2026-11-04):** The user deferred phone parity to a later phase. Do not gate the desktop/native freeform milestones on an iPhone implementation or add phone-specific UI patches during these phases.

**Approved design, staged implementation.** The initial freeform slice in PR #120 includes Song v22 note/Instrument data, whole/partial unpack commands, transport/export, a parent-attached desktop lane and direct Song-time note editing. Per-note cutoff automation conversion is implemented in desktop/native PR #129, preserving source Beat phase after unpacking; direct note-level freeform cutoff authoring through the shared interactive two-axis illustration is merged and Chrome/native CI-qualified in PR #147; advanced multi-parameter automation remains open. Reusable Beat extraction of captured cutoff movement is merged and CI-qualified in PR #141 (Beat v27 / Song v28), retaining the exact source-phase curve. Long-Song performance and phone parity remain separate. Freeform → reusable Beat from a selected 1–64-bar range is implemented in PR #124; it leaves source notes intact and does not automatically place the new Beat in the Song.

- Each Beat Track owns an attached child freeform lane, collapsed when empty. It is not an independently reorderable Song Track; its parent moves and reorders with it.
- A freeform lane can begin empty and contains multiple Instruments with ordinary Sound, Rack, note-expression and sample capabilities. It supports Song-position independent notes together with reusable Chunk placements.
- Move and unpack a Beat Clip into its attached lane by drag or an accessible action. Resolve source phase, repetitions, offsets, notes, instruments, expression, automation and external Assets. The original Beat remains reusable elsewhere; its Sound and Instrument identity stays shared with attached freeform while unpacked notes become independent Song-time instructions. No duplicate audio.
- Partial conversion splits a Beat Clip, preserving original source phase at the two unaffected sides. Notes crossing boundaries cannot be silently chopped. Convert to independent instructions, never a WAV bounce.
- Freeform passages can move horizontally with their contained events while remaining attached to their parent Track. Passage edges are organizing aids, not limits on where notes may be authored.
- A selected freeform range can create a new independent Beat; leave the freeform notes intact. Beat selections over 64 bars require explicit splitting.
- A single Song clock and Song scrubber position drive the freeform viewport; Beat's Chunk viewport remains independent. Pitched keys can illuminate when sounding.
- Editing source Beat notes updates linked Beat Clips but does not overwrite unpacked Song-position notes. Editing the source Beat Sound updates the same Instrument heard in its attached freeform. Every transformation is undoable and round-trips through the current .premidi format.

### Song pointer gestures (2026-11-06)

The Song ruler and its enlarged cursor hit target support click-and-drag seeking, quantized to the existing bar grid. The cursor and open Freeform viewport follow pointer movement before release; scrolled coordinates and the rendered empty timeline use the same mapping. `timelinePointer.js` owns pointer capture, the 180ms hold cue, motion threshold and cancellation. Escape, pointer cancellation, lost capture, window blur, page hide and workspace redraw clean up the gesture; cancelled scrubbing restores the original Song start. Keyboard ruler navigation remains available.

Holding or moving a Beat Clip outlines only its attached freeform tab and shows a quiet downward cue on the Clip. Ordinary horizontal movement has no drop popup. While the pointer is over the correct attached lane, a temporary placement outline and `release to make freeform · bar n` identify the exact destination. These cues never expand a dormant lane or move neighboring hit targets. Other Tracks' attached freeform lanes reject the drop visibly. A valid diagonal drop moves and unpacks at the previewed bar in one project transaction; Undo restores both the original Clip and its pre-drag start. Source Beat notes and Instruments remain shared/reusable. End-grip resizing retains priority and never triggers conversion.

The real-Chromium Pointer Events checks in `tests/song-pointer.browser.mjs` are part of `tests/song.browser.mjs`: they exercise hold, lateral movement, resize, scrolled scrubber dragging, marker capture, cancellation, foreign-lane rejection, exact drop timing and atomic undo/redo at wide and narrow desktop widths. Phone Freeform gesture qualification and physical Windows hardware acceptance remain separate open gates.

### Shared desktop workspace (2026-11-06)

### Canonical piano roll renderer, staged delivery (2026-11-06)

The canonical piano roll module is `editorPianoRoll.js`. **Merged and CI-qualified shared piano-row semantics (PR #205, 2026-11-06):** Beat and Song-time freeform now use the same `pianoRowMatchesNote`, `notesForPianoRow`, and `noteAtPianoStep` helpers to associate notes with pitched or Rack Sound rows and select notes at timeline steps. Song time remains absolute; Beat uses local Chunk time. This consolidates representation and hit-testing, not the remaining editor-host gesture orchestration.

**Current adapter boundary:** The workspace, actual pitched/Rack row construction, scale/key presentation and common gestures have one owner as described above. `studio.js` supplies Beat-local cell editing and `freeformUI.js` supplies Song-time event positioning, overlap selection, sustained-note clipping and Chunk placements. Continue to qualify these adapters against the shared controls rather than building another editor tree. Keep Beat-local navigation independent from the Song scrubber.

### Attached freeform is part of its Beat (2026-11-06)

**Approved user behavior:** A Beat Track starts with only a narrow freeform drop tab under its Beat lane. Dropping a Beat Clip onto the tab unpacks that occurrence and opens editing; an explicitly empty Track created through +track may instead offer a new independent Instrument. Opening an attached Beat lane must not ask for a second Instrument.

**Parent Sound identity, PR #200 (merged and CI-qualified):** New attached freeform instruments retain `sourceBeatId` and `sourceInstrumentId`. Their Sound IDs, layout, volume, names and Sound patches resolve from the parent Beat when editing, auditioning and playing Song notes; independent Song-time notes and Chunk placements remain owned by freeform. Presets and imported sample references are synchronized through the existing Song undo/save/validation boundary. Independently created Instruments belong to explicitly empty Tracks created through +track; no hypothetical legacy file cases are preserved. Once a Beat Clip is unpacked, the source Beat identity remains available through the recorded passage. If a Track contains multiple different source Beats, instruments are scoped to each source Beat, not arbitrarily merged by their names. Never create a second Synth or copy a Sound merely because a Beat's notes move into freeform.

**Viewport contract:** The Song scrubber owns the freeform viewport, including clicks on the Song ruler, Song bar field and Song playback. Beat's own Chunk view must remain independent and unchanged. Navigating bars from freeform changes the Song cursor, not a second independent bar cursor.

**Remaining acceptance work:** The shared workspace and pitched/Rack row surfaces are now in place. Retain and qualify the intentional Beat-local cell and Song-absolute event adapters, including dense layering, sampled Racks, automation and current-format export/import. Physical Windows 11 audio, microphone and editing acceptance remains open before overall rollout completion.

### Required gate: one canonical Sound Inspector (Beat + attached freeform)

**Decision (2026-11-04): consolidate the complete Sound editor before further standalone illustration polish.** An architectural inspection of `studio.js → renderSound()` and `freeformSoundUI.js → installFreeformSoundUI().render()` confirms two presentation/interaction assemblers around common `instrumentUI.js`, `samplerUI.js`, `soundIllustrations.js`, `soundEditPath.js`, Sound/Rack structures and native/browser DSP. Separate Song/Beat timing, freeform notes, and undo ownership are legitimate; separate Sound-editor UI trees are not. This decision **supersedes any plan to copy missing Beat controls into freeform** and is part of the same canonical Song/freeform rollout, not a new roadmap.

**Non-negotiable invariants**

- One Sound Inspector owns the Sound header, primary brightness/attack/release controls, Instrument and Sound level, stereo pan, gain-staging and measured scope, synth/sampler modules, effects and modulation UI, visual disclosure state, audio audition/preview, Sound/Rack selection, sample import, Sound browsing and factory/personal presets, save/import/export affordances and applicable Rack Sound actions. Beat and freeform **must not each construct their own copies** of those controls.
- Maintain one canonical parameter descriptor/path and applicable illustration grouping per ordinary synth and sample parameter. Migrate existing definitions from their current modules rather than invent a competing registry; `instrumentUI.js` / `samplerUI.js` and `soundIllustrations.js` remain the established sources during migration. Any registry introduced later must **replace**, not mirror, those definitions. No parameters, knobs, effects, modules or modulation routes may be removed to simplify visual mapping.
- Treat an educational illustration and its knobs as two input surfaces for **the same canonical value**. Drag/keyboard and conventional controls both commit via one context transaction; one sound change has one undo entry. Preserve real parameter ranges, gating rules, native/browser parity, and multi-axis interaction wherever musically meaningful. Every applicable control must be inventoried for illustration coverage; a genuinely nonvisual control keeps its functional knob and receives an explicit coverage rationale rather than being deleted.
- No alternate synth, sampler, PCM engine, playback fallback or `.premidi` Sound format. Beat and freeform retain their existing Sound/Rack patches and external asset references, Beat/Song timing, freeform parent ownership, long-note tails, vocal source recordings, versioned automation and independent project undo scopes. **No file migration** is justified solely by consolidating UI.
- Freeform note-level cutoff movement and Beat Instrument-level cutoff movement **reuse the same illustration/parameter UI where appropriate** but remain distinct automation targets with their original source-phase semantics. The Inspector receives a contextual automation capability; it must not silently reassign automation from a note to an Instrument or vice versa.
- Sound Inspector lifecycle must release prior graph listeners and scope subscriptions when switching context or Sound, retain only intended disclosure state, ignore stale asynchronous audition/import callbacks, avoid duplicate DOM IDs, and not force a destructive panel rerender during drag previews.
- The existing Beat desktop Sound layout is the initial visual baseline, not necessarily the only acceptable layout. Preserve the freeform-only useful features as the common editor grows; do not regress the educational illustrations being developed by the separate visualizer agent.

**Implementation sequence and acceptance gates (in order)**

1. **Inventory and context contract, not parallel implementation.** Record the actual Beat/freeform differences in one generated test inventory of `data-sound-path`, illustration kind, ordinary control, callback and applicability. Explicitly cover synth versus sample, pitched versus Rack, external sample import, reference pitch, cutoff automation, stage pan, gain, primary controls, modulation routes, effects, Sound save/browse, and action permissions. Audit documented exceptions. Define a small context adapter interface: read current Instrument/Sound/asset scope; commit one undoable parameter edit; ephemeral preview; audition; select Sound; invoke contextual browse/import/save/convert actions. An adapter provides **data and permissions, never its own set of knobs or illustrations**. Assert ownership with regression tests.
2. **Extract the Beat editor without changing appearance.** Move `studio.js → renderSound()` Sound-interface construction, including top-row controls, modules, measured scope, illustration wrapping and gain staging, into one mountable, context-agnostic Sound Inspector. Keep the Beat host's existing DOM placement, keyboard and accessible controls, sample/synth grouping, preset behavior and diagram disposal. `studio.js` becomes a Beat adapter with current Beat mutations/undo/preview. Capture a baseline Chrome UI/control-path inventory and verify it remains unchanged.
3. **Mount the exact same Inspector from freeform.** Reduce `freeformSoundUI.js` to a freeform adapter for Song Track/Instrument/Sound lookup, Song undo, shared samples, native audition and current Sound browsing/presets. Remove its independent Sound header, dials, module assembly, gain-staging drawing and preview logic after parity is verified. A freeform Sound then inherits any compatible new knob or illustration **automatically**, without copying a second renderer. Preserve attached lane/Chunk/note controls in `freeformUI.js`, not in the shared Sound Inspector.
4. **Complete visual/knob two-way coverage and prevent drift.** Test each applicable parameter path against the same registered controls and visual group in Beat and freeform. Verify dial → value → illustration, illustration → value → dial, simultaneous multi-axis changes, pointer/keyboard input, controlled previews, single-entry undo/redo, optional live audio audition, Sound/Rack switching, presets and sample asset lifetime. Check both positive and context-inapplicable cases. Fail CI if a new Sound control is added to one context but missing in the other without an explicit capability-based reason. Do not reduce the studio feature set to make tests pass.
5. **Reuse compatible processing in the vocal editor through the existing vocal completion gate.** Shared gain/filter/distortion/pan/envelope/movement/delay processing must use the canonical descriptors and illustrations **where semantics and parameter ranges genuinely match**. Retain vocal-only waveform trimming, recording latency, clip length/placement and source-asset ownership. Do not expose oscillator, Rack/Sound-zone or note-trigger controls on a timeline vocal merely to create superficial parity. Vocal completion is separately scored in the existing gate below, so this work cannot be falsely counted as completed just because Beat/freeform are unified.
6. **Qualify browser and native Windows, then ship.** Same-commit Chrome interaction snapshots, Sound-parameter-path coverage, native C++ versus browser audio-plan/PCM fixtures, persisted preset and `.premidi` ZIP round trips, Song/Beat/freeform undo and current-format export/import, Windows Tauri portable native playback/recording, folder-local data, relocation and recovery. New manual-download ZIP must be built from the qualified commit. Physical Windows 11 audio-device/listening checks remain an explicit final gate. Do not mark this consolidated Inspector complete until `studio.js` and `freeformSoundUI.js` no longer independently construct competing Sound editor surfaces.

### Remaining native streaming gate

The current native C++ session accepts at most **4,096 note/voice onsets per playback cycle**, a **10-minute cycle**, and a **16 MiB encoded event packet**, with separate bounded onset-density and voice-budget checks. These are real safety constraints, not arbitrary interface warnings. Removing the user-facing limit requires implementing a bounded, incremental native session protocol, rather than increasing constants.

**Approved architecture to pursue:** compile source-linked Beat, freeform, Chunk and vocal onsets on a non-audio thread into small absolute Song-time pages; prepare oscillator banks and sample/recording references before each handoff. Give the C++ device host a bounded queue and an explicit page-acknowledgment protocol. Keep the existing fixed-size real-time callback work budget. When a page is not ready, stop with a clear native error rather than silently switching to Web Audio or dropping musical instructions.

A page handoff must preserve still-sounding voices, their pitch/cutoff automation phase, release envelopes, delay tails, and sample playback position. Seek and loop reconstruction must work on either side of any page boundary. Song edits must invalidate only future pages, while preserving the current audible state. Page size and look-behind must be determined from measured event density and voice/effects lifetime, not fixed bars alone.

**Qualification before increasing limits:** compare browser and native event/PCM traces for 4,096-onset boundaries, long silent Songs over 10 minutes, high-density polyphony, overlapping vocal recordings, multi-bar sustained notes, irregular Chunk repeats, automation, transport seek/pause/loop and live edits. Measure memory and control-thread preparation costs and test callback starvation/fault recovery. Preserve portable-folder sample storage and run the existing Windows CI matrix. Physical Windows 11 output-device and microphone/latency checks remain separate acceptance items.

No unfinished stream/paging mechanism may be treated as supported just because the model accepts a longer Song; preserve current explicit preflight errors until full native qualification succeeds.

Do not simply raise native player limits to claim complete freeform support: sessions currently have bounded event counts and duration. Retain the canonical phone requirements in docs/phone-studio.md.
